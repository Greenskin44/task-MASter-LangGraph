# LangGraph Demo Examples

This file contains copy-paste ready examples for demonstrating all LangGraph implementations.
Each example is designed to work without modification in LangGraph Studio.

## STUDIO GRAPHS

These graphs demonstrate core LangGraph patterns and are ideal for learning and showcasing capabilities.

### 1. Parallelization: Web + Wikipedia Search

**Description:** Demonstrates parallel execution by simultaneously searching the web (Tavily) and Wikipedia, then synthesizing results into a coherent answer.

**Example 1: Simple Technology Question**
```json
{
  "question": "What is LangGraph?"
}
```

**Expected Output:** A comprehensive answer combining web search results and Wikipedia content about LangGraph, its purpose, and key features.

**Example 2: Technical Concept**
```json
{
  "question": "How does parallel execution work in distributed systems?"
}
```

**Expected Output:** An answer synthesizing information from multiple sources about parallel execution patterns, benefits, and implementation approaches.

**Example 3: Current Events**
```json
{
  "question": "What are the latest developments in large language models?"
}
```

**Expected Output:** Recent information from web searches combined with foundational knowledge from Wikipedia about LLM advancements.

### 2. Sub-Graphs: Log Analysis

**Description:** Demonstrates nested graph composition with two parallel sub-graphs that analyze logs for failures and summarize questions.

**Example 1: Basic Logs with Failures**
```json
{
  "raw_logs": [
    {
      "id": "1",
      "question": "How do I use Chroma vector store?",
      "docs": ["doc1", "doc2"],
      "answer": "Chroma is a vector database...",
      "grade": 2,
      "grader": "human",
      "feedback": "Poor retrieval quality"
    },
    {
      "id": "2",
      "question": "What is ChatOllama?",
      "docs": ["doc3"],
      "answer": "ChatOllama is a chat interface...",
      "grade": 1,
      "grader": "human",
      "feedback": "Incomplete answer"
    },
    {
      "id": "3",
      "question": "How to implement RAG?",
      "docs": ["doc4", "doc5"],
      "answer": "RAG combines retrieval with generation..."

```

**Expected Output:** 
- `fa_summary`: Analysis of failure patterns in graded logs
- `report`: Summary of question themes and topics
- `processed_logs`: List of processed log IDs from both sub-graphs

## DEPLOYMENT GRAPHS

These graphs are production-ready implementations for real-world use cases.

### Task Maistro: Personal Assistant with Memory

**Description:** A production-ready personal assistant that maintains long-term memory across three namespaces: user profile, todo list, and custom instructions. Uses Trustcall for intelligent memory updates and supports multi-category organization.

**Example 1: Profile Update**
```json
{
  "messages": [
    {
      "role": "user",
      "content": "Hi! My name is Alex and I work as a software engineer in San Francisco. I'm interested in AI, rock climbing, and cooking."
    }
  ]
}
```

**Expected Output:**
- Profile memory updated with name, location, job, and interests
- Natural response acknowledging the information
- Memory persisted in the profile namespace

**Configuration:**
```json
{
  "configurable": {
    "user_id": "user_123",
    "todo_category": "personal",
    "thread_id": "thread_001"
  }
}
```

**Example 2: Todo List Management**
```json
{
  "messages": [
    {
      "role": "user",
      "content": "I need to finish the project documentation by Friday and review the pull requests by tomorrow afternoon."
    }
  ]
}
```

**Expected Output:**
- Two tasks added to todo list with deadlines
- Confirmation message listing the added tasks
- Tasks stored in todo namespace with status "not started"

**Configuration:**
```json
{
  "configurable": {
    "user_id": "user_123",
    "todo_category": "work",
    "thread_id": "thread_002"
  }
}
```

**Example 3: Custom Instructions Update**
```json
{
  "messages": [
    {
      "role": "user",
      "content": "When I add tasks, always estimate the time to complete and suggest at least 2 specific solutions or approaches for each task."
    }
  ]
}
```

**Expected Output:**
- Instructions memory updated with user preferences
- Confirmation that preferences have been noted
- Future tasks will follow these instructions

**Configuration:**
```json
{
  "configurable": {
    "user_id": "user_123",
    "todo_category": "personal",
    "thread_id": "thread_003"
  }
}
```

**Example 4: Multi-Turn Conversation with Memory**
```json
{
  "messages": [
    {
      "role": "user",
      "content": "Add a task to buy groceries this weekend"
    }
  ]
}
```

Then in a follow-up interaction:
```json
{
  "messages": [
    {
      "role": "user",
      "content": "What tasks do I have coming up?"
    }
  ]
}
```

**Expected Output:**
- First interaction: Task added to todo list
- Second interaction: Assistant recalls the grocery task and any other tasks in memory
- Demonstrates memory persistence across conversations

**Configuration:**
```json
{
  "configurable": {
    "user_id": "user_123",
    "todo_category": "personal",
    "thread_id": "thread_004"
  }
}
```

**Example 5: Complex Task with Solutions**
```json
{
  "messages": [
    {
      "role": "user",
      "content": "I need to plan a team offsite event for 20 people next month. It should be fun and help with team bonding."
    }
  ]
}
```

**Expected Output:**
- Task added with estimated time to complete
- Multiple specific solutions suggested (e.g., escape room venues, outdoor activities, workshop facilitators)
- Task stored with deadline and actionable solutions
- Confirmation message with the task details

**Configuration:**
```json
{
  "configurable": {
    "user_id": "user_123",
    "todo_category": "work",
    "thread_id": "thread_005"
  }
}
```

**Notes:**
- The `user_id` identifies the user across all conversations
- The `todo_category` allows organizing tasks into different contexts (personal, work, etc.)
- The `thread_id` maintains conversation continuity within a session
- Profile updates happen silently without explicit confirmation to the user
- Todo updates are confirmed with details of what was added or changed
- Instructions updates are acknowledged but not detailed to the user

## EMAIL ASSISTANT

These graphs demonstrate automated email triage and response generation for executive assistants.

### Email Assistant: Automated Email Triage and Response

**Description:** An intelligent email assistant that triages incoming emails into three categories (respond, notify, ignore) and automatically drafts responses for emails that require replies. Uses tool-based actions for calendar management and email composition.

**Example 1: Meeting Request (RESPOND)**
```json
{
  "email_input": {
    "id": "email_001",
    "thread_id": "thread_001",
    "from_email": "sarah.johnson@techcorp.com",
    "to_email": "lance@langchain.com",
    "subject": "Quick sync on API documentation",
    "page_content": "Hi Lance,\n\nI hope this email finds you well. I wanted to reach out about the API documentation for the new LangChain endpoints. We're planning to integrate them into our product next week.\n\nCould we schedule a 30-minute call this week to discuss the authentication flow and rate limits? I'm available Tuesday afternoon or Thursday morning.\n\nLooking forward to hearing from you!\n\nBest regards,\nSarah Johnson\nSenior Engineer, TechCorp",
    "send_time": "2024-01-15T09:30:00Z"
  }
}
```

**Expected Output:**
- Classification: `respond`
- Agent checks calendar availability for Tuesday afternoon and Thursday morning
- Agent schedules meeting at available time slot
- Agent drafts response email confirming the meeting and addressing the API documentation topic
- Response includes meeting details and acknowledges the integration timeline

**Example 2: Technical Question (RESPOND)**
```json
{
  "email_input": {
    "id": "email_002",
    "thread_id": "thread_002",
    "from_email": "mike.chen@startup.io",
    "to_email": "lance@langchain.com",
    "subject": "Question about LangGraph memory persistence",
    "page_content": "Hey Lance,\n\nI've been working with LangGraph and have a question about memory persistence. I noticed the documentation mentions checkpoint-sqlite, but I'm wondering if there's support for PostgreSQL checkpointers in production environments.\n\nAlso, are there any best practices for handling long-running conversations with large state objects?\n\nThanks for your help!\n\nMike Chen\nCTO, Startup.io",
    "send_time": "2024-01-15T14:20:00Z"
  }
}
```

**Expected Output:**
- Classification: `respond`
- Agent drafts response addressing the technical questions
- Response mentions investigating PostgreSQL checkpointer support and provides timeline
- Response includes guidance on best practices for state management
- Professional and concise tone maintained

- Classification: `ignore`
- No response drafted
- Email identified as spam/suspicious
- No further action taken by the agent

**Notes:**
- The email assistant uses a two-stage workflow: triage → response (if needed)
- Triage classification is based on email content, sender, and configured rules
- RESPOND: Emails requiring direct replies (questions, meeting requests, client inquiries)
- NOTIFY: Important information worth knowing but not requiring a response (announcements, notifications, status updates)
- IGNORE: Irrelevant emails (marketing, spam, FYI threads with no action items)
- The response agent has access to tools for calendar management, email composition, and task completion
- All responses follow configured preferences for tone, style, and content
- The assistant can handle multi-turn interactions for complex email threads

## RESEARCH AGENT

These graphs demonstrate deep research workflows with multi-agent coordination and comprehensive report generation.

### Deep Research Agent: Multi-Agent Research Workflow

**Description:** A comprehensive research system that clarifies user requirements, generates research briefs, coordinates multiple research agents, and synthesizes findings into detailed reports. The workflow includes user clarification, research brief generation, multi-agent supervisor coordination, and final report synthesis.

**Example 1: Simple Research Topic (No Clarification Needed)**
```json
{
  "messages": [
    {
      "role": "user",
      "content": "I want to learn about LangGraph memory management and persistence strategies"
    }
  ]
}
```

**Expected Output:**
- System determines no clarification needed
- Generates research brief focusing on LangGraph memory management
- Supervisor coordinates research agents to gather information
- Final report includes:
  - Overview of LangGraph memory concepts
  - Checkpoint persistence strategies
  - Best practices for state management
  - Code examples and implementation patterns
  - Sources and citations

**Example 2: Research Topic Requiring Clarification**
```json
{
  "messages": [
    {
      "role": "user",
      "content": "I need information about AI safety"
    }
  ]
}
```

**Expected Output (First Interaction):**
- System asks clarifying questions such as:
  - What specific aspects of AI safety are you interested in? (technical approaches, policy, ethics, alignment research)
  - What is your background or use case for this research?
  - Are there specific time periods or developments you want to focus on?

**Follow-up Input (After Clarification):**
```json
{
  "messages": [
    {
      "role": "user",
      "content": "I need information about AI safety"
    },
    {
      "role": "assistant",
      "content": "To provide you with the most relevant research, I need to clarify a few things:\n\n- What specific aspects of AI safety are you interested in?\n- What is your background or use case?\n- Are there specific developments you want to focus on?"
    },
    {
      "role": "user",
      "content": "I'm a software engineer interested in technical approaches to AI alignment, particularly RLHF and constitutional AI. Focus on recent developments from 2023-2024."
    }
  ]
}
```

**Expected Output (After Clarification):**
- Generates detailed research brief incorporating user specifications
- Supervisor coordinates multiple research agents focusing on:
  - RLHF (Reinforcement Learning from Human Feedback) techniques
  - Constitutional AI approaches
  - Recent 2023-2024 developments
- Final report includes:
  - Technical overview of RLHF and constitutional AI
  - Recent research papers and developments
  - Implementation approaches and challenges
  - Comparison of different techniques
  - Sources with citations to recent papers

**Example 3: Complex Multi-Faceted Research**

  - Sources and citations

- The system adapts to user language - responses match the input language
- Research depth is comprehensive - reports are detailed and thorough
- Human-in-the-loop capability allows for iterative refinement
